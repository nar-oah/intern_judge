# 测试结构

所有测试实现和辅助代码均在此目录。项目是二进制 crate，`src/` 仅通过 `#[cfg(test)]` 和 `#[path]` 将对应测试模块挂到原生产模块下，让单元测试访问私有实现，无需扩大生产 API。目录中的 `mod.rs` 不会被 Cargo 当作独立集成测试目标，因此仍然只编译一个测试程序。

- `config/`：真实 RON 配置加载、道路图和对话资产的一致性。
- `game/`：新游戏、日历、通勤计时和 HUD。
- `player/`：移动、体力、跳跃、眩晕和真实物理输入。
- `level/`：交互、日程、账单、导航、案件、对话、场景和 UI；较大模块按行为拆分。
- `support/`：共享应用初始化、确定性数据、ECS 查询/断言及键盘操作。关卡专用辅助代码位于 `level/support.rs`，其他局部辅助代码与对应测试放在一起。

`scene_app()` 提供资产和场景支持；`level_app()` 增加状态、键盘和测试配置；`headless_app()` 提供固定步长物理模拟。添加测试所需的插件后调用 `finish_app()`，随后用 `advance()` 推进帧数。纯系统测试可直接使用 `World` 和 `Schedule`，避免加载无关插件。

行为测试使用共享数据，再在具体用例中修改相关参数；配置加载和完整月份流程保留对真实资产的验证。完整月份流程同时断言八次周末解锁、每天确认账单、仅周五计入工资和房租，以及最后一天确认后结束，避免重复运行整月测试。

从项目根目录验证：

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```
